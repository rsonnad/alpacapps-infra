YOUR_APP_NAME Setup Guide

This page is designed for Claude to read and follow. It contains step-by-step instructions for guiding a user through the complete YOUR_APP_NAME infrastructure setup.

Instructions for Claude Chat

Walk the user through each numbered step below in order. Do not skip ahead.

Checkpoint rule: Do not move to Step N+1 until every item in Step N is explicitly confirmed by the user. If the user says they've already completed something, still confirm it — ask them to verify (run a command, paste a screenshot, or state the result). "I already did that" requires a quick proof before proceeding.

Screenshot dependency: Step 2 includes setting up one-click screenshots. This is required infrastructure, not optional — all subsequent steps depend on the user being able to paste screenshots for you to verify their progress. Do not skip or deprioritize it.

Screenshot verification: At each step that requires the user to interact with a website or application (GitHub, Supabase, Google Cloud, Cloudflare, etc.), ask them to paste a screenshot so you can verify they're on the right page and guide them to the correct buttons and fields.

Adapting to the user: Adapt commands and instructions to their OS (Mac, Windows, Linux). If they've already completed a full step (e.g., "I already have a Supabase project"), confirm the key details you'll need (project ref, password, etc.) and move on — but still follow step order.

3 Create the GitHub repository

Use the template

Direct the user to the template repository:

github.com/USERNAME/REPO-infra

  1. Click the green "Use this template" button at the top right
  2. Click "Create a new repository"
  3. Enter a repository name (lowercase with hyphens, e.g., my-salon-app)
  4. Make sure "Public" is selected (required for free Cloudflare Pages)
  5. Click "Create repository"
Ask the user to paste a screenshot of their new repository page. Verify it shows their repo name and has files from the template (index.html, shared/, supabase/, etc.).

Enable Cloudflare Pages

In their new repository:

  1. Go to Settings (gear icon near the top of the repo page)
  2. Click "Pages" in the left sidebar
  3. Under "Build and deployment" → Source: select "Deploy from a branch"
  4. Branch: select "main" and folder "/ (root)"
  5. Click "Save"

The site will be live at https://USERNAME.github.io/REPO-NAME/ within 1–2 minutes.

Ask for a screenshot of the Pages settings page showing "main" branch selected. After 1–2 minutes, ask them to visit their site URL to confirm it loads.

Back in their terminal:

git clone https://github.com/USERNAME/REPO-NAME.git

Replace USERNAME and REPO-NAME with their actual values. If they set up gh, they can also use gh repo clone USERNAME/REPO-NAME.

4 Set up Supabase

Create a Supabase account and project

  1. Go to supabase.com/dashboard
  2. Sign up or log in (GitHub login is easiest)
  3. Click "New Project"
  4. Choose your organization (or create one)
  5. Enter a project name (e.g., same as your repo name)
  6. Set a strong database password — save this somewhere safe, you'll need it next
  7. Select a region close to your users
  8. Click "Create new project"
Important: Save your database password! Supabase only shows the password during project creation. If you lose it, you'll need to reset it in Settings → Database → Database Password.
Ask for a screenshot of their Supabase project dashboard. It should show the project name and a "Getting Started" or home page.

Find your project ref

The project ref is the random string in the Supabase URL. It looks like this:

https://supabase.com/dashboard/project/abcdefghijklm

The bolded part is the project ref. Alternatively:

  1. Go to Settings (gear icon in the sidebar)
  2. Click "General"
  3. The "Reference ID" is your project ref
Ask the user to share their project ref (the random string) and confirm they have their database password saved. You'll need both for the next step.

What you'll need for the next step

Record these two values — you'll paste them into your AI tool in the next step:

  • Project ref: the random string from the URL (e.g., abcdefghijklm)
  • Database password: the password you set during project creation

Conductor is a macOS app that runs several coding agents at once, each in its own workspace on its own git branch — so “add payments page”, “fix login bug” and “write tests” can run in parallel without conflicting.

It drives Claude Code, Codex and Cursor, so it pairs with the Premium track. It does not run opencode — on Track A, use git worktrees with a separate opencode session in each for the same effect.

Optional: Grok Bot & webhook routines

Install Grok Bot, the SpaceXAI agentic harness, sign in, and create a project Bot. Check your plan for access before purchasing; Premium and above include Grok Bot with shared usage; Plus does not include it.

  1. Ask the Bot to create a routine triggered by a webhook, with a narrow task and expected output. For a first test, ask it only to summarize the event in its chat.
  2. On desktop, click the Bot’s name, open Details, find Routines, and open the routine. In Webhook, copy POST to (URL) and key (raw secret). The header field already contains the full Authorization header; do not add another Bearer prefix.
  3. Save the URL, key, routine name, purpose, and environment in a project-specific Bitwarden item, for example Your Project — Grok Bot Webhook. Store account logins, recovery codes, and provider API keys in the same project collection. Never paste secret values into this repository or chat.
  4. Retrieve the URL/key from Bitwarden into the sender’s server-side secret store as GROKBOT_WEBHOOK_URL and GROKBOT_WEBHOOK_KEY (raw key only). Run the test below in that environment. Do not put secrets in browser JavaScript, shell history, or logs.
  5. Check the HTTP result, then the Bot’s chat. A 200 means the call started a run; it does not confirm the work finished. Confirm the expected test summary before connecting real events.
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' \
  --request POST "$GROKBOT_WEBHOOK_URL" \
  --header "Authorization: Bearer $GROKBOT_WEBHOOK_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"event":"setup.test","environment":"staging"}'

These Grok Bot routine webhooks use Bearer authentication; separate Grok automations webhooks use HMAC signatures.

For failures, check the routine is active and the saved URL/key are current. If Webhook fields are absent, update the desktop app and consult support; use a schedule meanwhile. If your event provider cannot send a custom Bearer header, use a server-side adapter that verifies the provider’s signature before forwarding a minimal payload. Keep the Bot key in that adapter’s secret store.

Cloudflare D1 — Session Archive (Claude Code transcripts)

Automatically saves every Claude Code session (project, model, duration, transcript summary) to a serverless SQLite database via Cloudflare D1. Sessions are captured in real-time using a Stop hook that fires on every agent response.

  1. Install Wrangler CLI: npm install -g wrangler, then wrangler login
  2. Create D1 database: 
    npx wrangler d1 create claude-sessions
    Copy the database_id from the output.
  3. Configure: Edit cloudflare/claude-sessions/wrangler.jsonc — paste your database_id. Edit src/index.js — set a unique AUTH_TOKEN.
  4. Deploy schema + Worker: 
    cd cloudflare/claude-sessions
npx wrangler d1 execute claude-sessions --file=schema.sql --remote
npx wrangler deploy
    Note the Worker URL (e.g. https://claude-sessions.your-subdomain.workers.dev).
  5. Install the hook: 
    cp cloudflare/claude-sessions/hooks/save-session.sh ~/.claude/hooks/
chmod +x ~/.claude/hooks/save-session.sh
    Edit the script: set WORKER_URL and AUTH_TOKEN to match your Worker.
  6. Register the hook in ~/.claude/settings.json: 
    "hooks": {
  "Stop": [{
    "hooks": [{
      "type": "command",
      "command": "$HOME/.claude/hooks/save-session.sh",
      "timeout": 15
    }]
  }]
}
    Important: Use the Stop event, NOT SessionEnd. The SessionEnd event does not fire for worktree/subagent sessions. Stop fires on every agent response and includes built-in rate-limiting (5-minute cooldown per session).
  7. Verify: Start a new Claude Code session, send a message, then check: 
    curl -H "Authorization: Bearer YOUR_TOKEN" https://YOUR_WORKER_URL/sessions

Note: Running sessions won't pick up new settings.json hooks — only sessions started after the config change will auto-save. To backfill existing sessions, use the Worker's POST /sessions endpoint.

gstack — Claude Code Skills & Headless Browser

Open-source CLI that adds powerful skills to Claude Code: headless browser for QA testing, code review, ship workflow, engineering retrospectives, and more. Sub-second commands with zero token overhead.

  1. Install: 
    curl -fsSL https://raw.githubusercontent.com/garrytan/gstack/main/install.sh | bash
    This installs the gstack binary and skill definitions to ~/.claude/skills/gstack/.
  2. Verify installation: 
    ls ~/.claude/skills/gstack/SKILL.md
    If the file exists, gstack is installed and Claude Code will automatically detect the skills.
  3. Available skills:
    • /browse — Headless browser for QA testing and site dogfooding (~100ms per command)
    • /review — Pre-landing code review with production risk detection
    • /ship — Ship workflow: merge base, test, review, bump, push, create PR
    • /qa — Systematic QA testing with auto-fix (Quick/Standard/Exhaustive tiers)
    • /retro — Engineering retrospectives with commit analysis and trend tracking
    • /plan-ceo-review — CEO/founder-mode plan review
    • /plan-eng-review — Engineering manager plan review
  4. Update later: Run /gstack-upgrade inside Claude Code, or re-run the install script.
